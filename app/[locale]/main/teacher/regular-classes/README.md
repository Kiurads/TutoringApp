# app/main/teacher/regular-classes

A single list page, symmetric to `app/main/student/regular-classes/page.tsx`: auth-gated, fetches `fetchRegularClassesByTeacher(email)` and renders `RegularClassesTable` with `role="teacher"` (which is what makes the table show each row's *student* name and gate Accept/Refuse to the teacher, per `regular-classes-table.tsx`'s role-branching), plus the shared `ToastNotification` for post-action banners. Unlike the student side, there's no `request/` subroute here — a teacher never initiates a recurring-class request in this app (`regular-classes.actions.ts` has no teacher-initiated `RegularClass` creation, only `requestRegularClass` which is always student-driven; contrast with one-off classes, where `create-class-as-teacher.ts` does let a teacher initiate). A teacher's only actions on this page are accept/refuse a pending request or cancel an active series, all via `RegularClassActionModals` embedded in the table.
