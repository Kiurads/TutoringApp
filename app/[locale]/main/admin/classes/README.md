# app/main/admin/classes

A single, simple page: fetches every `Class` row via `fetchClasses()` (`app/lib/actions/classes.actions.ts` — no filtering, no auth/role check visible in this file itself, so authorization presumably relies entirely on the surrounding admin layout/route-group gating rather than a check in this page — worth confirming with the auth-rbac-engineer domain if you're auditing this route's access control) and renders the read-only `ClassesTable` (`app/ui/main/classes/classes-table.tsx`) with a simple count header. No pagination, filtering, or search — every class in the system renders in one table, which could become a real performance/usability concern as class volume grows. No actions available from this view (`ClassesTable` has no buttons) — an admin who needs to act on a specific class currently has no dedicated admin class-detail route; they'd need to go through one of the participant-facing detail pages instead (both `[id]/page.tsx` pages under `student/classes` and `teacher/classes` do allow `role === "admin"` through their `isParticipant` checks).
