# app/ui/main/calendar

The weekly drag-to-schedule calendar view shared by student and teacher "My Calendar" pages (`app/main/student/calendar` and `app/main/teacher/calendar`, both pass a `basePath` prop so the same component routes to the right role's URLs).

## Key files

- **`weekly-schedule.tsx`** — the main calendar grid (`WeeklySchedule`). A from-scratch 7-day/hour-grid implementation (no calendar library), covering hours 7:00–22:00 (`GRID_START`/`GRID_END`) at `HOUR_PX = 64` px/hour:
  - **Click-and-drag scheduling**: mouse-down on an empty grid cell starts a drag tracked via a `useRef` (`activeDrag`) rather than component state, specifically so the global `window` `mousemove`/`mouseup` listeners (attached once in an effect with an empty dependency array) never see a stale closure over the current drag — only the ref is read inside those global handlers. On mouse-up, the dragged range is snapped to 30-minute slots (`getSlot`) and opens a "Schedule a Class" confirmation `<dialog>`, which on confirm pushes to `${basePath}/classes/request?startTime=...&duration=...` — pre-filling the booking form via query params rather than creating anything directly from the calendar.
  - **Local-timezone bucketing**: classes are grouped into day columns via `toDateStr(new Date(cls.startTime))` — since `cls.startTime` is a UTC instant (per `ClassDataCalendar`'s own documented contract in `classes.actions.ts`), this bucketing is *timezone-correct by construction*: a class at 11pm Pacific / 7am UTC lands under "today" for a Pacific viewer even though it's already "tomorrow" in UTC. The inline comment calls this out explicitly — don't "fix" this by reading UTC date parts instead of local ones, that would put classes on the wrong day for non-UTC viewers.
  - **Live "now" indicator**: a horizontal red line + dot rendered at the current hour position, recomputed on every render (not on an interval) — so it only visibly moves on some other state change causing a re-render, not a live ticking clock.
  - **Real `<dialog>` modal** (`showModal()`/`close()`) for the schedule-confirmation flow, same reasoning as `class-action-modals.tsx` (focus trap + Escape-to-close for free) — the inline comment explicitly cross-references that file.
  - **Mobile scroll hint**: a small `sm:hidden` line above the grid ("Scroll sideways to see the full week") — the grid itself has a fixed `min-w-[640px]` inner wrapper inside an `overflow-x-auto`, so on narrow viewports the week scrolls horizontally with no built-in affordance signaling that more days exist off-screen; this hint text is the fix for that (a recent addition — check `git log`/`git blame` on this file if you need the exact history).
- **`class-card.tsx`** — `CalendarClassCard`, the individual event block rendered inside a day column. Reads `classData.startTime` via **local** `Date` getters (`getHours()`/`getMinutes()`), not UTC getters — its own inline comment says this must match the parent `WeeklySchedule`'s local-timezone bucketing, "same as every other now/local-time computation in the parent." Height/position are computed from `hourPx`/`gridStart` props passed down from the parent's constants, and a status-to-color map (`STATUS_STYLE`) covering `requested`/`scheduled`/`completed`/`refused`/`cancelled` with a neutral `FALLBACK` for anything else — a third independent status-color mapping in this domain, alongside `class-status-badge.tsx`'s badge colors and `class-info-card.tsx`'s `STATUS_BORDER` (see that directory's README) — keep all three in sync when a status value changes meaning or a new one is added.

## How it fits together

Purely a read+deep-link surface: it fetches nothing itself (`classes: ClassDataCalendar[]` is passed in as a prop, sourced from `fetchClassBySelfCalendar` in `classes.actions.ts` by the parent page) and creates nothing directly — dragging a range only pre-fills the create-class form's query params, the actual `Class` row is created by the normal `create-class-as-student`/`create-class-as-teacher` flow once the student/teacher finishes the form. Clicking an existing class block navigates to that class's detail page (`${basePath}/classes/${id}`).

## Gotchas

- Any change to how `startTime` is parsed here must preserve the local-timezone-getter convention in both files — mixing local and UTC getters between the parent's day-bucketing and the child's block positioning would visually misplace events for non-UTC viewers.
- Three independent status→color maps exist across this domain (this directory's `STATUS_STYLE`, `class-status-badge.tsx`'s badge map, `class-info-card.tsx`'s `STATUS_BORDER`) — none of them share a single source of truth.
- The "now" line only updates on re-render, not on a ticking interval — don't assume it's a live clock if you're debugging why it appears frozen.
