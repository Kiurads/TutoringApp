# `app/ui/main/payments`

Shared UI components for displaying already-settled payments — tables, receipts, and their supporting print/retry controls. Used across admin, student, and teacher payment surfaces (not role-specific itself).

## Files

- **`payments-table.tsx`** — `"use client"` table with a local search filter (student name, teacher name, subject, or payment id substring match, case-insensitive). Takes `initialPayments: Payment[]` as a prop — data is fetched server-side by the caller and passed in, not fetched here. Renders a `PAYOUT_STATUS_BADGE`/`PAYOUT_STATUS_LABEL` pair keyed by `payoutStatus` (`transferred` → success/"Paid out", `pending` → warning/"Pending", `failed` → error/"Failed" + inline `payoutError` text + `<RetryPayoutButton>`, `not_applicable` → ghost/"—"). Currently only consumed by `app/main/admin/payments/page.tsx` — the type shape (`amount`, `platformFeeAmount`, `teacherPayoutAmount` all as plain `number`, not Prisma `Decimal`) implies the caller must have already converted Decimals via `.toNumber()` before passing props across the server/client boundary (Prisma Decimal methods don't survive serialization — see the admin page's own comment on this).
- **`receipt.tsx`** — pure presentational component, `receipt: PaymentReceipt` prop (the type is imported from `app/lib/actions/paymets.actions.ts`, not redefined here). Renders a full receipt layout: student/teacher identity, class subject + start time + duration, payment date, and an amount/fee/payout breakdown table, plus the raw Stripe `intentId` as a "transaction reference" footer line. **Print convention**: the outer wrapper uses `print:border-none print:p-0 print:max-w-none` (Tailwind's `print:` variant) so the card chrome disappears and the receipt fills the page width when printed — this pairs with the `print:hidden` convention used on the *pages* that embed `<Receipt>` (see `app/main/student/payments/[id]/receipt/page.tsx` and the teacher equivalent), which hide the back-button/print-button row entirely when printing. If you add new receipt-adjacent chrome, wrap it in `print:hidden` (or give it `print:`-prefixed layout overrides) to keep the printed output receipt-only.
- **`print-button.tsx`** — trivial `"use client"` button, just `window.print()` behind an icon button. No print-specific logic of its own; relies entirely on the `print:` Tailwind classes elsewhere (in `receipt.tsx` and the receipt pages) to control what actually renders on the printed page.
- **`retry-payout-button.tsx`** — `"use client"` button that calls `retryFailedPayout(paymentId)` from `app/lib/actions/payouts.actions.ts` inside a `useTransition`, shows a spinner while pending, an inline error string on failure, and permanently swaps to a static "Retry queued" label on success (no automatic re-check of whether the retry actually succeeded — it just confirms the retry was *queued*, not that the payout is now `transferred`). Only rendered inline inside `payments-table.tsx` when a row's `payoutStatus === "failed"`.

## How it fits together

- `payments-table.tsx` → `retry-payout-button.tsx` (composition, same directory).
- `receipt.tsx` and `print-button.tsx` are composed together by the two receipt pages (`app/main/student/payments/[id]/receipt/page.tsx`, `app/main/teacher/payments/[id]/receipt/page.tsx`), not by anything in this directory — this directory only supplies the pieces.
- Data for `receipt.tsx` comes from `fetchPaymentReceipt(paymentId, viewerEmail)` (`app/lib/actions/paymets.actions.ts`), which is viewer-scoped: it returns `null` (not an error) if the requesting email doesn't match either the payment's student or teacher, so the calling page can render a generic `notFound()`.
- Data for `payments-table.tsx` currently comes only from the admin payments page's own `prisma.payment.findMany` query — there's no student/teacher-facing equivalent list view in this codebase today (see the `app/main/student/payments` and `app/main/teacher/payments` READMEs: those directories contain only a `[id]/receipt` route, no index/list page).

## Non-obvious conventions / gotchas

- `PAYOUT_STATUS_BADGE`/`PAYOUT_STATUS_LABEL` are duplicated verbatim between `payments-table.tsx` (this directory) and `app/main/teacher/payouts/page.tsx` — if the `payoutStatus` enum ever gains a new value or the copy changes, both places need updating; there's no shared constant.
- `receipt.tsx` formats `platformFeeAmount` with a leading minus sign (`−{receipt.platformFeeAmount.toFixed(2)}€`) using a Unicode minus (`−`, U+2212), not a hyphen — cosmetic, but worth preserving if touching that line so it doesn't silently become a hyphen under find-and-replace.
